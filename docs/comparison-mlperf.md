# `s3aibench` vs MLPerf Storage

`s3aibench` is **not** an MLPerf-compliant benchmark and does not claim to be.
This note explains where the two tools overlap, where they differ, and how to
translate results from one to the other for internal planning.

## What MLPerf Storage measures

MLPerf Storage issues an end-to-end training-IO workload generated by the
reference framework (e.g., DLIO on PyTorch). It exercises the *entire* path:
the framework's dataloader, shuffle buffers, collective ops, and storage.
The published accuracy/throughput number is tied to a reference model.

## What `s3aibench` measures

`s3aibench` is a **storage-only** micro-benchmark. It drives the S3 data path
with workload shapes that look like training traffic (PRD §§5.1–5.8) but it
never runs a model, never shuffles tensors, and never synchronises across
ranks. Everything downstream of the S3 response body is discarded.

## When to use which

| Need | Use |
|------|-----|
| "What does my storage platform do under realistic S3 pressure?" | `s3aibench` |
| "Can this platform keep a specific training job fed at N samples/sec?" | MLPerf Storage |
| "Did this storage change regress us?" | `s3aibench` (stable shapes, fast runs, JSON report for CI gates) |
| "What's our competitive number?" | MLPerf Storage (industry-standard) |

## Translation guidance

- **Throughput ceiling.** An `s3aibench` large-object GET result is an
  *upper bound* on any MLPerf Storage number on the same hardware, because
  MLPerf adds framework overhead.
- **Small-object IOPS.** `s3aibench`'s `smallobject` workload approximates
  MLPerf's shuffled WebDataset shard-probe phase, but without shard
  coalescing. Expect `s3aibench` numbers to be higher than MLPerf
  equivalents on the same endpoint.
- **Tail latency.** Both tools report p99. MLPerf's p99 is per-sample;
  `s3aibench`'s is per-op. The two are comparable only on uniform object
  workloads.

## What we do not do

- Ship MLPerf reference plans. We intentionally avoid any file named
  `mlperf-*.yaml` to prevent confusion.
- Publish numbers framed as MLPerf results. Any claim to compliance would
  require running MLPerf's reference harness under its disclosure rules.
